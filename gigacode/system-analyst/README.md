## Системный аналитик

**system-analyst.md** — основной агент для перевода бизнес-требований в техническую документацию.

### Задачи
- Анализ требований и выделение функциональных/нефункциональных характеристик
- Создание технических спецификаций
- Описание API в формате OpenAPI
- Построение диаграмм последовательности (PlantUML)
- Документирование структуры базы данных (DBML)

### Доступные директории
- `doc-as-code/` — техническая документация
- `src/main/resources/api/openapi.yml` — OpenAPI спецификация
- `.puml` файлы — диаграммы последовательности
- `.dbml` файлы — схемы базы данных

### Исключения
- Не пишет миграции базы данных (только описывает структуру в `.dbml`)
- Не модифицирует файлы вне разрешённого scope

## Скиллы

### dbml-writer

Специализированный скилл для работы с Database Markup Language.

**Когда использовать:**
- Документирование структуры базы данных
- Описание таблиц, отношений, индексов
- Изменения в схеме БД

**Формат выхода:** `.dbml` файлы

---

### openapi-writer

Специализированный скилл для работы с OpenAPI 3.0.1 спецификацией.

**Когда использовать:**
- Добавление новых API endpoints
- Обновление существующих endpoint'ов
- Создание новых DTO моделей

**Команды для генерации:**
```bash
mvn generate-sources
```

**Формат выхода:** `src/main/resources/api/openapi.yml`

---

### plantuml-writer

Специализированный скилл для создания диаграмм последовательности PlantUML.

**Когда использовать:**
- Визуализация бизнес-процессов
- Описание взаимодействия компонентов
- Документирование потоков данных

**Правила форматирования:**
- REST запросы в одну строку
- SQL запросы в одну строку

**Формат выхода:** `.puml` файлы

## Workflow

1. **Системный аналитик** анализирует требования
2. При необходимости вызывает соответствующий **скилл** для специализированной задачи
3. Результаты сохраняются в соответствующие директории
4. Все документы соответствуют существующим конвенциям проекта

## Структура директорий

```
doc-as-code/
├── database_dbml/     # .dbml файлы
├── system_functionality/  # .puml диаграммы
├── admin-panel/       # .puml диаграммы админки
└── [module]/          # другие модули
```

## GigaCode Skill Creator
skill/
├── SKILL.md              (обязательный - метаданные + инструкции)
├── scripts/              (опциональный - исполняемый код)
├── references/           (опциональный - документы для загрузки)
└── assets/               (опциональный - файлы для вывода)

SKILL.md

Обязательный файл
Содержит метаданные (frontmatter YAML) и инструкции
Загружается в контекст при активации skill

scripts/

Содержит исполняемый код
Это детерминированные, многократно используемые скрипты
Токенно-эффективны
Могут выполняться без загрузки в контекст
Примеры: bash скрипты для генерации кода, валидации и т.д.

references/

Содержит документы, загружаемые по мере необходимости
keeps SKILL.md лёгким (до 500 строк)
Детальная информация переносится в отдельные файлы
Загружаются в контекст только когда нужны

assets/

Содержит файлы, используемые в выводе
Текстуры, изображения, шаблоны, конфигурации
Никогда не загружаются в контекст
Используются только в выходных данных
