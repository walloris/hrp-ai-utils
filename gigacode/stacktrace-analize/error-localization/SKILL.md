# Bug Localization

**Цель**: найти наиболее вероятное место причины бага. без исправления кода.

## Запрещено
- Исправлять код
- Менять файлы
- Исользовать вместе с другими агентами

## Алгоритм
1. Сначала определи симптом:
    - как воспроизводится баг;
    - что ожидалось;
    - что произошло фактически.
2. Найди стартовую точку:
    - stack trace;
    - сообщение об ошибке;
    - ближайший модуль, связанный с симптомом.
3. Исследуй только ближайшую цепочку вызовов вокруг симптома:
    - входные данные;
    - изменения состояния;
    - побочные эффекты;
    - граничные условия.
4. На каждом шаге решай:
    - это место похоже на источник бага;
    - или нужно подняться на 1 уровень выше по вызовам.
5. Остановись, когда найдено 1–3 наиболее вероятных места.

## Ограничения
- Не чини код.
- Не рефактори код.
- Не сканируй весь проект.
- Не меняй файлы и не добавляй комментарии в код.
- Не исследуй больше 3 уровней вызовов подряд без новой зацепки.
- Не делай больше 3 итераций анализа без промежуточного вывода.
- Если начинаешь повторять те же действия без новых данных — остановись и запроси уточнение.

## Формат вывода (ОБЯЗАТЕЛЬНО)

```markdown
---
**🏁 РЕЗУЛЬТАТ АНАЛИЗА**
- **Симптом:** [что происходит в понятных словах, например: "заказ не сохраняется при оплате, потом что это поле не заполнено"]

- **Наиболее вероятные места:**
  1. `путь/к/файлу` → `ClassName` — `functionName()` — [причина в 1–2 предложениях]
  2. `путь/к/файлу` → `ClassName` — `functionName()` — [причина в 1–2 предложениях]
  3. `путь/к/файлу` → `ClassName` — `functionName()` — [причина в 1–2 предложениях]

- **Уверенность:** высокая / средняя / низкая
---
```
