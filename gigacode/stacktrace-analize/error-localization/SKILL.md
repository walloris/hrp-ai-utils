# Error Localization

Цель: найти наиболее вероятное место причины бага. Не исправляй код и не меняй файлы.

## Используй, когда
- есть воспроизводимый баг;
- есть stack trace, ошибка, некорректное поведение или регрессия;
- нужно сузить поиск до конкретного файла, функции или участка кода.

## Алгоритм
1. Сначала определи симптом:
   - как воспроизводится баг;
   - что ожидалось;
   - что произошло фактически.
2. Найди стартовую точку:
   - stack trace;
   - сообщение об ошибке;
   - ближайший модуль, связанный с симптомом.
3. Исследуй только ближайшую цепочку вызовов вокруг симптома:
   - входные данные;
   - изменения состояния;
   - побочные эффекты;
   - граничные условия.
4. На каждом шаге решай:
   - это место похоже на источник бага;
   - или нужно подняться на 1 уровень выше по вызовам.
5. Остановись, когда найдено 1–3 наиболее вероятных места.

## Ограничения
- Не чини код.
- Не рефактори код.
- Не сканируй весь проект.
- Не меняй файлы и не добавляй комментарии в код.
- Не исследуй больше 3 уровней вызовов подряд без новой зацепки.
- Не делай больше 3 итераций анализа без промежуточного вывода.
- Если начинаешь повторять те же действия без новых данных — остановись и запроси уточнение.

## Формат ответа
Верни результат в таком виде:

- Симптом: ...
- Наиболее вероятные места:
  1. `ClassName` — `functionName()` — причина в 1–2 предложениях
  2. `ClassName` — `functionName()` — причина в 1–2 предложениях
  3. `ClassName` — `functionName()` — причина в 1–2 предложениях
- Уверенность: low / medium / high
- Что ещё нужно от пользователя: логи, stack trace, входные данные, шаги воспроизведения
