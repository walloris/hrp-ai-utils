# Skill: onboarding

Этот скилл выполняется только после активации.

## Режим работы

Сначала определи режим:

- `init` — памяти нет, создать с нуля
- `update` — память есть, обновить изменившиеся секции
- `repair` — память частично сломана, восстановить недостающее или исправить пути

Правила выбора режима:

- если `.gigacode/memory/` отсутствует — `init`
- если отсутствует один или несколько файлов памяти — `repair`
- если отсутствует `.gigacode/settings.json` — `repair`
- если пути в `.gigacode/settings.json` не совпадают с фактическими — `repair`
- если память существует и пользователь просит обновить контекст — `update`
- если проект существенно изменился с момента последнего обновления памяти — `update`

## Шаг 1 — Исследование проекта

1. Прочитай `README*`, `docs/` и корневые markdown-файлы с описанием проекта
2. Изучи структуру директорий на глубину 2–3 уровня
3. Найди build/config файлы:
   - `build.gradle.kts`, `build.gradle`, `settings.gradle`, `pom.xml`
   - `pyproject.toml`, `requirements.txt`, `poetry.lock`
   - `package.json`, `pnpm-lock.yaml`, `yarn.lock`
   - `Cargo.toml`, `go.mod`
   - `Makefile`, `Taskfile.yml`
   - `docker-compose.yml`, `compose.yml`, `Dockerfile`
   - `.env.example`, `.env.sample`
4. Найди тесты, линтеры, форматтеры, CI/CD, infra-файлы и нестандартные корневые подсистемы
5. Определи:
   - название проекта
   - назначение проекта
   - стек технологий
   - точки входа
   - команды запуска
   - команды тестов
   - основные модули
   - внешние интеграции
   - архитектурные паттерны
6. Не делай предположений
7. Если факт не найден — используй `<не определено>`

## Шаг 2 — Полнота анализа

Проводи анализ в два прохода.

### Проход 1 — Извлечение фактов

Для конечных наборов сущностей проекта найди источник истины и полный список элементов.

Примеры:
- типы шаблонов
- модули
- сервисы
- пайплайны
- джобы
- воркеры
- команды CLI
- интеграции
- entrypoints
- профили конфигурации

Источники истины:
- enum
- sealed class
- config
- schema
- registry
- factory
- switch/match
- документация проекта

Для каждого набора:
1. Найди полный список элементов
2. Зафиксируй количество элементов
3. Сохрани количество для проверки покрытия

### Проход 2 — Проверка покрытия

Для каждого конечного набора:
- сравни полный список с тем, что описано в памяти
- пометь статус:
  - `описано`
  - `найдено, но не описано`
  - `не подтверждено`
- если найдено 6 элементов, а описано 4 — дополни память до полного покрытия
- не завершай онбординг, пока покрытие не станет полным или пока отсутствующие данные не будут явно помечены как `<не определено>`

Перед завершением задай себе проверку:
- Что я мог пропустить?
- Все ли типы, модули, команды, интеграции и шаблоны перечислены полностью?
- Есть ли конечный набор, который я описал не полностью?

## Шаг 5 — Настройка автозагрузки памяти

Создай или обнови `.gigacode/settings.json`:

```json
{
  "context": {
    "fileName": [
      ".gigacode/memory/project.md",
      ".gigacode/memory/architecture.md",
      ".gigacode/memory/stack.md",
      ".gigacode/memory/conventions.md"
    ]
  }
}
```

Правила:
- использовать только пути из `.gigacode/`
- если `settings.json` уже существует и содержит дополнительные валидные настройки — сохранить их
- обновлять только `context.fileName`, если это можно сделать без потери пользовательских настроек
- не использовать `systemPrompt` внутри `settings.json` как обязательный механизм старта сессии

## Шаг 6 — Проверка `.gitignore`

Убедись, что `.gigacode/` добавлен в `.gitignore`.

Если записи нет — добавь:

```gitignore
.gigacode/
```

## Шаг 7 — Правила обновления

- в режиме `init` создай все файлы
- в режиме `update` меняй только изменившиеся секции
- в режиме `repair` восстанавливай только отсутствующее или повреждённое
- не перезаписывай файл полностью, если достаточно локального обновления
- если старый факт больше не подтверждается проектом — удали его или замени на `<не определено>`

## Шаг 8 — Валидация результата

Перед завершением проверь:

1. Все 4 файла памяти существуют
2. `.gigacode/settings.json` существует
3. Пути в `.gigacode/settings.json` совпадают с фактическими файлами
4. `.gigacode/` добавлен в `.gitignore`
5. В памяти нет неподтверждённых утверждений
6. Все неизвестные данные помечены как `<не определено>`
7. Для конечных наборов сущностей проверено покрытие
8. Если найден конечный набор, он отражён в памяти полностью или явно помечен как неполный

## Жёсткие правила

- не придумывай информацию
- подтверждай факты только файлами проекта
- если факт не найден, используй `<не определено>`
- не меняй пользовательский код, если задача только в онбординге
- перед дальнейшей работой читай файлы памяти, если они уже загружены в контекст
- не считай анализ завершённым без проверки полноты покрытия
