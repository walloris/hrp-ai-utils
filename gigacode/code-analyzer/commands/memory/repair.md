# Command: memory:repair

Режим: **repair** — структура `.gigacode/` повреждена или неполна.

Восстанавливает только отсутствующие или сломанные части без пересоздания того, что работает.

---

## Шаг 0 — Диагностика

Проверь состояние `.gigacode/`:

### Проверь memory-файлы
- [ ] `.gigacode/memory/project.md` существует и не пуст
- [ ] `.gigacode/memory/architecture.md` существует и не пуст
- [ ] `.gigacode/memory/stack.md` существует и не пуст
- [ ] `.gigacode/memory/conventions.md` существует и не пуст
- [ ] `.gigacode/memory/references/naming.md` существует
- [ ] `.gigacode/memory/references/layering.md` существует
- [ ] `.gigacode/memory/references/error-handling.md` существует
- [ ] `.gigacode/memory/references/testing.md` существует
- [ ] `.gigacode/memory/references/api-patterns.md` существует

### Составь список проблем
Зафиксируй явно: что отсутствует, что повреждено, что содержит нерабочие пути.

---

## Шаг 1 — Чтение существующей памяти

Прочитай все файлы, которые существуют и не пусты.
Это база для восстановления — не трогай то, что работает.

---

## Шаг 2 — Восстановление отсутствующих файлов

Восстанавливай только то, чего не хватает.

### Если отсутствуют memory-файлы

Для каждого отсутствующего файла: исследуй проект и воссоздай файл.

Приоритет восстановления:
1. `project.md` — без него нет базы
2. `stack.md` — определяет технологии
3. `architecture.md` — структура проекта
4. `conventions.md` — соглашения команды
5. `references/*.md` — детальные паттерны

**Исследование для восстановления:**

1. Прочитай `README*`, `docs/` и корневые markdown-файлы
2. Изучи структуру директорий на глубину 2–3 уровня
3. Найди build/config файлы:
   - `build.gradle.kts`, `build.gradle`, `settings.gradle`, `pom.xml`
   - `pyproject.toml`, `requirements.txt`, `poetry.lock`
   - `package.json`, lockfiles
   - `Cargo.toml`, `go.mod`
   - `Makefile`, `Taskfile.yml`
   - `docker-compose.yml`, `compose.yml`, `Dockerfile`
   - `.env.example`, `.env.sample`

Если факт не найден — используй `<не определено>`.

Если существующие файлы памяти содержат данные о проекте — используй их как источник при воссоздании недостающих файлов.

---

## Шаг 3 — Содержимое восстанавливаемых файлов

### `project.md`
Обязательно включи:
- описание проекта
- цель
- дату обновления памяти (пометить как `восстановлено`)
- точки входа
- команды запуска/тестов/линта
- ключевые директории
- покрытие (`Entrypoints`, `Main modules`, `External integrations`)
- короткий раздел `Использование памяти`

### `architecture.md`
Обязательно включи:
- тип архитектуры
- основные компоненты
- поток данных
- интеграции
- конечные наборы сущностей с покрытием

### `stack.md`
Обязательно включи:
- язык и рантайм
- основные зависимости
- базы данных/хранилища
- сборку, тесты, CI, контейнеризацию

### `conventions.md`
Обязательно включи:
- только подтверждённые соглашения
- confidence по основным категориям
- таблицу когда читать references
- coding rules

### `references/*.md`
Каждый файл должен содержать:
- `Observed patterns`
- `Good examples`
- `Bad fit`

---

## Шаг 4 — Финальная проверка

1. Убедись, что `.gigacode/` добавлен в `.gitignore`
2. Проверь:
   - все memory-файлы существуют
   - неизвестные данные помечены `<не определено>`
   - покрытие сущностей полное
   - `conventions.md` основан на реальных примерах
   - для conventions выставлен confidence
   - в `project.md` нет раздела про references
   - в `conventions.md` нет дублирующего раздела `## References`

3. Ответь пользователю:

```text
✅ Онбординг завершён

Режим: repair

Проблемы обнаружены:
- <список того, что было сломано или отсутствовало>

Восстановлено:
- <список восстановленных файлов>

Без изменений (уже корректно):
- <список нетронутых файлов>

Проект: <название>
Стек: <основные технологии>
Покрытие:
- Entrypoints: <n из n>
- Main modules: <n из n>
- Key finite sets: <n из n>
```

---

## Жёсткие правила

- не придумывай информацию
- подтверждай факты только файлами проекта
- если факт не найден, используй `<не определено>`
- не трогай файлы, которые работают корректно
- не меняй пользовательский код
- не считай repair завершённым без финальной проверки всех чекбоксов из Шага 0
- не считай conventions установленными без реальных примеров
