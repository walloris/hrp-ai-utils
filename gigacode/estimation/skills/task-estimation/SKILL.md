# Task Estimation

Комбинированная оценка задач по времени, сложности и истории. Формат вывода — Story Points с обоснованием.

---

## Critical Path

- **База**: оцени по времени или эталону (1ч=1, 1-2ч=2, 2-4ч=3, 4-8ч=5, 8-12ч=8, 12-14ч=13, 14-28ч=21 SP)
- **Сложность**: -1..+2, определяется через чеклист кода, тестов, зависимостей
- **Неопределённость**: -1..+2, определяется через чеклист архитектуры и инфраструктуры
- **Формула**: `final = base + complexity + uncertainty`, округлить до Фибоначчи

## Основные инструкции

### Шаг 1: Анализ кода

- Читаешь только файлы, которые **точно будут изменены**
- Не нашёл за 5 файлов — фиксируй как допущение* и оценивай по описанию
- Покрытие тестами всегда проверяй. И тесты которые надо будет изменить тоже смотри.

---

### Шаг 2: Базовая оценка

Если есть эталонная задача из таблицы калибровки — сравни с ней в первую очередь.
Если эталона нет — используй таблицу часов (часы = условный средний разработчик команды, не конкретный исполнитель):

```
<1 часа    → 1 point
1-2 часа   → 2 point
2-4 часа   → 3 points
4-8 часов  → 5 points
8-12 часов → 8 points
12-14 часа → 13 points
14-28 часов  → 21 points
```

---

### Шаг 3: Корректировка на СЛОЖНОСТЬ

Ответь на каждый вопрос: **да / нет**. Подсчитай количество «да».

| # | Сигнал сложности |
|---|---|
| 1 | Затронуто больше 3 файлов/классов? |
| 2 | Создаются новые компоненты, контракты или точки интеграции? |
| 3 | Бизнес-логика сложная — много условий, edge cases, доменные правила? |
| 4 | Тестов на изменяемые части нет? |
| 5 | Покрытие тестами затратно — сложные моки, интеграционный setup? |
| 6 | Есть внешние API, очереди или сторонние сервисы? |
| 7 | Есть риск каскадных эффектов — что-то ещё может сломаться? |

```
0-1 «да» → -1  (знакомая территория)
2-3 «да» →  0  (обычная задача)
4-5 «да» → +1  (заметная сложность)
6-7 «да» → +2  (высокая сложность)
```

---

### Шаг 4: Корректировка на НЕОПРЕДЕЛЁННОСТЬ

Ответь на каждый вопрос: **да / нет**. Подсчитай количество «да».

| # | Сигнал неопределённости |
|---|---|
| 1 | Архитектурное решение неочевидно — нужно проектировать? |
| 2 | Нужна координация с другими командами или сервисами? |
| 3 | Нужна миграция БД? |
| 4 | Нужны изменения в конфигурации / env / feature flags? |
| 5 | Нужны изменения под нагрузку или есть риск производительности? |

```
0   «да» → -1  (неопределённости не выявлено)
1   «да» →  0  (чёткие требования)
2-3 «да» → +1  (требуется проектирование)
4-5 «да» → +2  (высокая неопределённость)
```

---

### Шаг 5: Итоговая формула

```
final = base + complexity + uncertainty

Диапазон: min = 1+(-1)+(-1) = -1 → 1 SP (минимум)
           max = 8+(+2)+(+2) = 12  → 13 SP
```

Округлить до ближайшего числа Фибоначчи: **1, 2, 3, 5, 8, 13**

> Результат ≥ 13 — задача не умещается в один спринт. **Разбить обязательно.**

## Примеры

### Пример 1: Баг с отменой запросов

**Время**: 5 часов → база **3 points**

**Сложность** (7 сигналов):
- Затронуто 3-4 файла? — нет
- Новые компоненты/контракты? — нет
- Сложная бизнес-логика? — нет
- Тестов нет? — да ✓
- Дорогое покрытие? — да ✓
- Внешние API? — да ✓
- Риск каскада? — нет
  → 3 «да» → **0**

**Неопределённость** (5 сигналов):
- Нужно проектировать? — нет
- Координация с командами? — нет
- Миграция БД? — нет
- Конфиг/env? — нет
- Нагрузка/перфоманс? — нет
  → 0 «да» → **-1**

**Итого**: 3 + 0 + (-1) = 2 → **2 points**

---

### Пример 2: Простой баг-фикс

**Время**: 2 часа → база **1 point**

**Сложность**: 0 сигналов → **-1**
**Неопределённость**: 0 сигналов → **-1**

**Итого**: 1 + (-1) + (-1) = -1 → **1 point** (минимум)

---

### Пример 3: Новая фича с интеграцией

**Время**: 20 часов → база **8 points**

**Сложность**: 5 сигналов (>3 файлов, новые компоненты, бизнес-логика, нет тестов, внешний API) → **+1**
**Неопределённость**: 4 сигнала (проектирование, координация, миграция, env) → **+2**

**Итого**: 8 + 1 + 2 = 11 → **13 points** → **разбить!**

---

## Антипаттерны

- **Смешивание времени и SP**: Story Points — относительная сложность, не абсолютное время
- **Игнорирование истории**: повторяющиеся задачи оцениваются на основе прошлых спринтов
- **Пропуск чеклиста**: быстрая интуитивная оценка — основная причина недооценки инфра-работ и тестов
- **Задачи >8 SP без разбивки**: всегда дробить до планируемых единиц

### Расчёт
**Эталон**: [ссылка на эталонную задачу, если использовалась] / [или: таблица часов, n-n ч → n points]

**Сложность** (4 из 7 сигналов → +1):
- Затронуто больше 3 файлов — да ✓
- Новые компоненты/контракты — нет
- Сложная бизнес-логика — нет
- Тестов нет — да ✓
- Дорогое покрытие тестами — да ✓
- Внешние API/очереди — да ✓
- Риск каскада — нет

**Неопределённость** (2 из 5 сигналов → +1):
- Нужно проектировать — да ✓

- Миграция БД — да ✓
- Конфиг/env/flags — нет
- Нагрузка/перфоманс — нет

**Итого**: 3 + 1 + 1 = 5 → **5 points**

### Разбивка
- Анализ и проектирование: 1 point

- [Описание рисков]

- [Зависимости]
